
# BUG-002: Parser Accepts an Array Without a Closing Bracket

## Severity
Medium

## Component
TOML Decoder

## Affected Version
toml 0.10.2

## File
toml/decoder.py

## Description

The TOML parser accepts an incomplete array even when its closing square bracket is missing.

This allows malformed TOML documents to be parsed successfully instead of raising a syntax error.

## Steps to Reproduce

1. Install `toml==0.10.2`.
2. Run:

```python
import toml

document = "A = [1,"
result = toml.loads(document)

print(result)
```

## Expected Result

The parser should reject the document because the array is missing its closing `]`.

Python's standard-library `tomllib` rejects this input with `TOMLDecodeError`.

## Actual Result

The `toml` package accepts the document and returns:

```python
{'A': [1]}
```

## Evidence

### 1. Differential Testing

Hypothesis discovered the following minimal failing document:

```toml
A = [1,
```

The two parsers behave differently:

| Parser | Result |
|---|---|
| toml 0.10.2 | Accepts and returns `{'A': [1]}` |
| Python tomllib | Rejects with `TOMLDecodeError` |

### 2. Direct Decoder Test

Run:

```python
from toml.decoder import TomlDecoder

decoder = TomlDecoder()

print(decoder.load_array('[1,'))
print(decoder.load_array('[1]'))
```

Both calls return:

```text
[1]
[1]
```

This confirms that the decoder's array-parsing method accepts the incomplete array.

## Suspected Root Cause

In `toml/decoder.py`, the `load_array()` method uses:

```python
a = a[1:-1].split(',')
```

This removes the first and last characters without first verifying that the last character is actually `]`.

The function subsequently parses the extracted elements and returns the array without validating the missing closing bracket.

Relevant source lines:

- Lines 947–951: Array text extraction and splitting.
- Lines 1023–1033: Array elements are parsed and the result is returned.

## Impact

Applications that use this parser to validate configuration files may silently accept malformed TOML instead of reporting a syntax error.

This can lead to inconsistent parsing behaviour between applications using different TOML implementations.

## One-Line Reproduction

```python
import toml; print(toml.loads("A = [1,"))
```

Expected observed output from the defective library:

```python
{'A': [1]}
```

## Hypothesis Shrinking

Hypothesis reduced the differential parsing failure to:

```toml
A = [1,
```

This is the minimal example used to reproduce the parser acceptance mismatch.
